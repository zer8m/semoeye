# 세모눈
**혼자서 생각하고 있던 아이디어를, 검토진이 검토하여 아이디어를 발전시키는 것을 도와주는 서비스**
기획안·사업 아이디어·제안서·발표 초안을 붙여넣으면 안건 성격에 맞는 최대 4명의 AI 검토자가 각자의 질문으로 검토하고, 의견이 모인 지점과 갈린 지점을 가른 뒤 진행 / 보류 / 폐기를 판정한다. 검토자 중 한 명은 항상 반대하는 입장으로 비판적인 시각을 제공한다.

## 왜 만들었나
| 기존 방법 | 문제 |
| --- | --- |
| AI에게 검토 요청 | 질문 방식이나 검토 기준에 따라 피드백이 피상적이거나 일반론에 그칠 수 있다 |
| 주변 사람에게 요청 | 시간을 들여 상세한 피드백을 주기 어렵고, 관계를 고려해 비판적인 의견을 삼가는 경우가 있다 |
| 스스로 검토 | 자신의 관점과 가정에 갇혀 새로운 시각에서 문제를 발견하기 어렵다 |

## 핵심 기능
- 검토진: 8명의 검토자(찬성자, 비사용자, 개발자, 제작자, 운영자, 결정권자, 심사위원, 법률 관리인 + 반대자 ) 중 4명이 동시에 검토한다
- 결과 리포트 제공: 4명의 검토자들이 검토한 내용을 요약된 리포트로 제공한다

## 기술 스택
- 프런트엔드:	Next.js + TypeScript + CSS Modules + Tailwind
- 백엔드: Node.js
- LLM: Timely API 연동
- 데이터베이스: Supabase
- 배포: Vercel
- UI 디자인: Cosmos ui 디자인 참고(https://styles.refero.design/style/eb804e3a-1b75-446c-8374-114bbabaf0cd)
- 업로드 문서 처리:	pdfjs-dist, mammoth, jszip, cfb (브라우저 내), docling (서버 전처리)

## 구조

```
src/
├── app/
│   ├── page.tsx              랜딩 (로그인·회원가입 모달 포함)
│   ├── review/               안건 입력 → 검토진 선택 → 검토 세션
│   ├── records/              내 기록
│   └── api/
│       ├── review/route.ts   LLM 스트리밍 프록시 + 폴백
│       └── extract/route.ts  docling 전처리 프록시
├── components/
│   ├── session/              검토 세션 화면, 상세 검토 모달, 토론
│   ├── reviewers/            검토진 선택
│   └── auth/                 로그인·회원가입
└── lib/
    ├── prompt.ts             스킬 로드 + 확장 블록
    ├── reviewers.ts          검토자 8명 정의 (페르소나·질문·루브릭)
    ├── match.ts              검토자 자동 배정
    ├── embed.ts              해시 임베딩 (256차원)
    ├── parser.ts             리포트 파싱 (판정·채점·위험도·토론 블록)
    ├── extract.ts            브라우저 내 문서 텍스트 추출
    └── supabase.ts           저장 (Supabase / localStorage)
```
